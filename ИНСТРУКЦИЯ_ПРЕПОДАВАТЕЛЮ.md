# Инструкция преподавателю

Откройте этот файл. Студентам отправьте всю папку `Notiii`; каждому скажите открыть только его файл `students/<имя>/Task.md`.

**Обозначения в заданиях:** `[ ]` — ещё не начато; `[-]` — выполняется или есть блокер; `[x]` — пункт сделан, проверен и показан преподавателю. Студент меняет отметку сам. Вы ставите «принято» только после того, как увидели результат.

## Как провести первое занятие

- [ ] Откройте PowerShell в этой папке `Notiii`.
- [ ] Запустите `docker compose up --build -d`.
- [ ] Выполните `docker compose ps`. Убедитесь, что сервисы не завершились с ошибкой. Если Docker Engine недоступен, остановитесь и передайте диагностику Кириллу.
- [ ] Откройте `http://localhost:5173` и `http://localhost:8000/api/v1/health/`. Зафиксируйте фактический результат. Не говорите, что сервис работает, если URL не ответил.
- [ ] До создания таблиц подтвердите или исправьте предлагаемые поля в разделе «Перед началом кода» ниже. Запишите решение и дату в `docs/ai/DECISIONS.md`.
- [ ] Выдайте каждому только его `Task.md`. Скажите: «Работаем в этой общей папке. Меняй только файлы из своего задания. Один файл одновременно меняет один человек. После каждого шага покажи мне файл и проверку».
- [ ] Идите по очереди выполнения ниже. Если шаг не прошёл — не переходите через него; запишите ошибку и попросите Кирилла помочь с запуском.

## Перед началом кода: подтвердите первый срез

Это предложение, а не уже принятое решение:

- Composer: обязательное имя.
- Work: название, описание, сложность.
- У Work может быть несколько Composer.
- Первый API: `GET /api/v1/works/` и необязательный поиск `?q=...` по названию или имени композитора.
- Ответ списка содержит `count` и `results`; пустой список — HTTP 200 и `results: []`.
- В первой версии нет PDF, авторизации, жанров, инструментов и пагинации.

Скажите, что оставить, убрать или изменить. Пока вы не записали своё решение в `docs/ai/DECISIONS.md`, Мадиар не запускает `makemigrations`, а Арыс не делает API каталога.

## Очерёдность работы

Работайте над общей папкой Notiii. Не создавайте клоны и дополнительные папки с документацией.

- [ ] **Кирилл:** проверяет Docker и health URL. Если среда не запустилась, вся команда сначала получает точную причину.
- [ ] **Мадиар:** после вашего решения создаёт модели, показывает миграцию вам, затем применяет её и запускает тесты моделей.
- [ ] **Арыс:** параллельно может написать тесты уже существующего health. Endpoint списка он начинает после готовности и вашей проверки моделей Мадиара.
- [ ] **Халил:** сначала создаёт типы и API-функцию. Подключает настоящую страницу после того, как Арыс закончил endpoint.
- [ ] **Аделя:** создаёт карточку и сетку по согласованным типам. Халил подключает их к странице после отдельного показа карточек.
- [ ] **Кирилл:** повторяет основные сценарии через браузер и API, помогает каждому воспроизвести запуск.

## Как проверить работу каждого

Для каждой задачи попросите студента сделать четыре вещи:

- [ ] Открыть изменённый файл и показать конкретное изменение.
- [ ] Запустить команду из его `Task.md` и дождаться окончания.
- [ ] Показать результат команды, HTTP-ответ или экран. Если есть ошибка — прочитать её полностью.
- [ ] Объяснить изменение своими словами и ответить: «Какой пример доказывает, что это работает? Что случится при ошибочном входе?»

Не пишите «готово», если вы не видели проверку. Не закрывайте Jira-задачу по одному наличию кода. Назначения Jira обновляйте только после проверки аккаунта конкретного человека и существующей задачи в проекте `SDT`.

## Когда закончено первое общее задание

- [ ] Django применяет миграции и проходит тесты.
- [ ] `GET /api/v1/works/` возвращает реальные строки из PostgreSQL; автоматические тесты Арыса проверяют список, поиск и пустой результат.
- [ ] React запрашивает этот endpoint, показывает загрузку, данные, пустой результат и ошибку.
- [ ] Карточки Адели показывают реальные поля API.
- [ ] Кирилл или другой участник повторил запуск по корневому `README.md`.

Если любой пункт не выполнен, отметьте его как «не готово» и запишите конкретный следующий шаг.

## Открытые проектные записи

Они нужны вам для истории решений и Jira, но студентам для первого задания читать их не нужно:

- `docs/ai/PROJECT_CONTEXT.md` — факты о проекте.
- `docs/ai/DECISIONS.md` — что преподаватель подтвердил и что остаётся черновиком.
- `docs/ai/SESSION_STATE.md` — текущий статус.
- `docs/ai/WORK_BREAKDOWN.md` — уже существующие Jira-ключи; проверяйте их, прежде чем создавать задачи.
