## Твоя цель

Сделать frontend, который запрашивает список из Django и честно показывает пользователю: загрузку, список, отсутствие результатов или ошибку. Запрос и экран должны использовать один согласованный JSON.

## Какие файлы ты меняешь

- `frontend/src/api/works.ts` — тип ответа и функция GET.
- `frontend/src/pages/CatalogPage.tsx` — поиск и состояние страницы.
- `frontend/src/App.tsx` — подключение готовой страницы, только после показа преподавателю.

Карточки `WorkCard` и `WorkGrid` принадлежат Аделе. Не создавай их сам и не меняй её CSS.

## Перед началом

- [ ] Получи от преподавателя точные поля JSON. Не придумывай поля от себя.

Узнай у преподавателя точные поля JSON. До одобрения нельзя считать черновик API контрактом. Для первого среза предлагаются запросы:

```http
GET /api/v1/works/
GET /api/v1/works/?q=соната
```

Предлагаемый ответ: `{ "count": 1, "results": [...] }`. Не придумывай отсутствующие поля и не показывай фиктивные записи как серверные.

## Часть 1. Сделай типы и запрос

### Как работать

Открой корень `Notiii` в VS Code. Файлы открывай через Explorer слева, терминал — через **Terminal → New Terminal**. Меняй только `works.ts`, `CatalogPage.tsx` и разрешённый пункт `App.tsx`. Сохраняй `Ctrl+S` после каждого малого изменения и показывай результат. Если типы не совпадают, не маскируй это через `any` или непроверенное `as`: поставь `[-]`, запиши текст ошибки и попроси Арыса/преподавателя сверить контракт.

- [ ] **Шаг 1. Открой существующий пример**

Открой `frontend/src/api/health.ts`. Найди `fetch`, `await`, `response.ok`, `response.json()`, `AbortSignal`. Объясни преподавателю, почему HTTP 404 сам по себе не означает, что Promise от `fetch` перешёл в rejected.

Прочитай по порядку: `fetch` начинает запрос и возвращает Promise; `await` ждёт ответ; HTTP 404/500 всё равно дают объект `Response`; `response.ok` отдельно показывает, успешен ли HTTP-статус; `response.json()` асинхронно читает тело. Сетевой сбой обычно отклоняет Promise самого `fetch`. Покажи преподавателю соответствующие строки в `health.ts`.

- [ ] **Шаг 2. Открой уже созданный `frontend/src/api/works.ts` и замени TODO-комментарий реализацией.**

- [ ] Опиши TypeScript-типы одной работы и ответа списка по утверждённому JSON.
- [ ] Создай функцию `getWorks(params, signal?)`, возвращающую `Promise` с типизированным списком.
- [ ] Создай URL через `URLSearchParams`. Если поиск пустой или из пробелов, параметр q не добавляй.
- [ ] Вызови `fetch('/api/v1/works/...')`, передай `Accept: application/json` и сигнал отмены.
- [ ] Если `response.ok` равен `false`, выбрось понятную ошибку с HTTP-кодом.
- [ ] Прочитай JSON и проверь хотя бы, что это объект с `count` и массивом `results`; не утверждай тип только через `as`, не проверив вход.
- [ ] Сетевой сбой и отмену запроса не показывай как успешный пустой список.

Пиши функцию поэтапно: (1) тип одной работы; (2) тип ответа `{ count, results }`; (3) `URLSearchParams`; (4) добавление `q` только если `q.trim()` не пуст; (5) `fetch` по `/api/v1/works/` с `Accept` и `signal`; (6) проверка `response.ok`; (7) чтение JSON; (8) проверка, что ответ — объект, `count` — число, `results` — массив. После этапов 1–4 сначала запусти сборку. `Promise<T>` — значение типа T, которое придёт позже; `AbortSignal` позволяет отменить запрос.

Пока endpoint Арыса не готов, проверь типы сборкой; не говори, что запрос получил живые данные.

В PowerShell из корня `Notiii` перейди в папку frontend и запусти:

```powershell
cd frontend
npm run build
npm run lint
```

- [ ] **Часть 2. Сделай страницу каталога**

Начинай, когда Арыс показал работающий endpoint и Аделя показала `WorkGrid` с понятными props.

Не начинай до этих двух показов. Попроси Арыса показать фактический JSON, а Аделю — имя props и его тип. Сверь названия полей API и компонента. Если контракт изменился, команда сначала согласует один вариант, а затем обновляет типы.

- [ ] Открой уже созданный `frontend/src/pages/CatalogPage.tsx` и замени TODO-комментарий страницей каталога.
- [ ] При открытии страницы запроси список.
- [ ] Добавь поле поиска и кнопку отправки. Отправляй введённый q на backend; не фильтруй только уже загруженный список.
- [ ] Перед новым запросом показывай loading и не выдавай старые результаты за новые.
- [ ] Различай четыре состояния: loading; список; пустой `results`; HTTP/сетевую ошибку.
- [ ] Добавь кнопку «Повторить» при ошибке.
- [ ] Используй `AbortController`: при размонтировании компонента отменяй запрос; не показывай отмену как ошибку.
- [ ] Защити интерфейс от гонки: если быстрые поиски завершаются не по порядку, старый ответ не должен заменить более новый.
- [ ] Подключи `WorkGrid` Адели, передавая ему реальные `results` через props.
- [ ] Подключи `CatalogPage` в `App.tsx`. Не переписывай весь `App.tsx`: сохрани верхнюю структуру и подключение приложения.

Логика по шагам: до ответа — loading; успешный непустой массив — карточки; успешный пустой массив — «Ничего не найдено»; HTTP/сеть завершились ошибкой — сообщение и кнопка повтора. При новом запросе не выдавай старые карточки за новые. Отмени предыдущий запрос или сравни номер текущего запроса, чтобы поздний старый ответ не перезаписал новый. Отмена не должна выглядеть ошибкой.

## Часть 3. Проверь в браузере

- [ ] Из `frontend` запусти `npm run build` и `npm run lint`.
- [ ] Открой `http://localhost:5173`.
- [ ] В DevTools → Network покажи GET `/api/v1/works/`, статус и JSON.
- [ ] Найди часть названия; повтори для имени автора.
- [ ] Введи то, чего нет: ожидается понятное пустое состояние, не ошибка.
- [ ] В PowerShell из корня выполни `docker compose stop backend`. Повтори запрос на странице: ожидается сообщение об ошибке и кнопка повтора.
- [ ] Верни backend командой `docker compose start backend`, дождись запуска и нажми повтор: страница должна снова получить ответ.
- [ ] Начни один поиск, сразу другой: на экране должны остаться результаты последнего поиска.

Чтобы увидеть запрос: открой сайт → `Ctrl+Shift+I` → **Network** → фильтр **Fetch/XHR** → перезагрузи. Нажми строку `works/`: вкладка **Headers** показывает URL и статус, **Response** — JSON. При поиске проверь наличие `?q=...`. Покажи фактический запрос преподавателю; проверка сборкой не доказывает, что API был вызван.

Если frontend-тестовой библиотеки нет в `package.json`, не устанавливай её без согласования. Сначала обязательны build/lint и эти ручные сценарии.

### Если проверка не проходит

Если сборка ругается на поле, сверь его с утверждённым JSON и типом Адели. Если Network не показывает запрос, проверь, вызвала ли страница функцию `getWorks`. Если показывает статус ошибки — сообщи его Арысу/Кириллу. Если статус 200, но JSON отвергнут, сравни вкладку **Response** с проверкой структуры в `works.ts`. Не подставляй фиктивные данные для сокрытия ошибки.
