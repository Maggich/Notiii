# 2. Первое задание — научиться работать с Promise

## Что такое Promise?

Представь, что ты заказал еду.

Тебе её не выдают моментально. Ты ждёшь.

В программировании происходит то же самое.

Когда React запрашивает произведения у Django, ответ не приходит мгновенно.

**Promise — объект, который представляет результат асинхронной операции: он может появиться позже или завершиться ошибкой.**

У него три состояния:

- `pending` — операция ещё выполняется.
- `fulfilled` — операция успешно завершилась.
- `rejected` — произошла ошибка.

## Задание 2.1 — создать свой Promise

Напиши:

```
const promise = new Promise<string>((resolve) => {
  setTimeout(() => {
    resolve("Произведения загружены");
  }, 2000);
});

promise.then((result) => {
  console.log(result);
});
```

### Что тут происходит?

`new Promise` — создаёт Promise.

`resolve()` — сообщает, что операция успешно завершена.

`setTimeout()` — в этом учебном примере имитирует ожидание 2 секунды.

`.then()` — выполняется после успешного завершения Promise.

### Что нужно проверить?

Запусти код и убедись, что сообщение появилось примерно через 2 секунды.

Затем объясни преподавателю, почему сообщение не появляется сразу.

## Задание 2.2 — Promise с ошибкой

```
const promise = new Promise<string>((resolve, reject) => {
  setTimeout(() => {
    reject(new Error("Сервер недоступен"));
  }, 2000);
});

promise
  .then((result) => {
    console.log(result);
  })
  .catch((error) => {
    console.error(error.message);
  });
```

### Твоя задача

1. Объяснить разницу между `resolve` и `reject`.
2. Объяснить, зачем нужен `.catch()`.
3. Изменить код так, чтобы Promise завершался успешно.
4. Сделать ещё один Promise, который завершится ошибкой.
5. Добавить `.finally()` и проверить, что он выполняется в обоих случаях.

**Приёмка:** ты самостоятельно показываешь успешный и неуспешный Promise.

# 3. Второе задание — async/await

Promise можно обрабатывать через `.then()`, но часто удобнее использовать `async/await`.

Пример:

```
function getMessage(): Promise<string> {
  return Promise.resolve("Привет, Халиль");
}

async function showMessage() {
  const message = await getMessage();

  console.log(message);
}

showMessage();
```

`async` — функция возвращает Promise.

`await` — ожидает результат Promise внутри асинхронной функции.

## Задание 3.1

Создай функцию:

```
function getWorks(): Promise<string[]> {
  return Promise.resolve([
    "Лунная соната",
    "Ноктюрн",
    "Времена года",
  ]);
}
```

Теперь напиши **самостоятельно** функцию `loadWorks`, которая:

- вызывает `getWorks()`;
- использует `await`;
- выводит произведения в консоль;
- перехватывает ошибку через `try/catch`;
- выводит сообщение «Загрузка завершена» через `finally`.

Ожидаемый результат:

```
Лунная соната
Ноктюрн
Времена года
Загрузка завершена
```

## Задание 3.2

Измени `getWorks()` так, чтобы она возвращала отклонённый Promise:

```
return Promise.reject(new Error("Ошибка загрузки"));
```

Убедись, что ошибка попадает в `catch`, а `finally` всё равно выполняется.

**Приёмка:** ты объясняешь разницу между `.then()` и `await`, а также между `catch` и `finally`.

# 6. Пятое задание — получение данных в React

Это основная часть работы.

Ты должен научиться использовать `useEffect`, `useState` и Promise вместе.

Начни с такого примера:

```
import { useEffect, useState } from "react";

function WorkCatalog() {
  const [works, setWorks] = useState<Work[]>([]);
  const [loading, setLoading] = useState(true);
  const [error, setError] = useState<string | null>(null);

  useEffect(() => {
    async function loadWorks() {
      try {
        const data = await getMockWorks();
        setWorks(data);
      } catch {
        setError("Не удалось загрузить произведения");
      } finally {
        setLoading(false);
      }
    }

    void loadWorks();
  }, []);

  if (loading) {
    return <p>Загрузка произведений...</p>;
  }

  if (error) {
    return <p>{error}</p>;
  }

  return <WorkList works={works} />;
}
```

Для запуска этого примера `Work`, `getMockWorks` и `WorkList` должны быть определены или корректно импортированы.

### Что здесь происходит?

`useState([])` — хранит произведения.

`useState(true)` — хранит состояние загрузки.

`useState(null)` — хранит текст ошибки либо `null`.

`useEffect()` — запускает загрузку после появления компонента на странице.

`await getMockWorks()` — ожидает данные.

`setWorks(data)` — сохраняет полученные произведения.

`catch` — обрабатывает ошибку.

`finally` — выключает индикатор загрузки.

`[]` — список зависимостей эффекта. При обычном монтировании эффект запускается; в режиме разработки React Strict Mode может запускать его повторно для проверки корректности логики.

# 8. Седьмое задание — настоящий fetch

После утверждения API преподавателем и Арысом ты должен заменить учебные данные запросом к Django.

Пример предполагаемого запроса:

```
async function fetchWorks(): Promise<Work[]> {
  const response = await fetch("/api/v1/works/");

  if (!response.ok) {
    throw new Error(`HTTP ошибка: ${response.status}`);
  }

  const data: unknown = await response.json();

  if (!Array.isArray(data)) {
    throw new Error("Неверный формат ответа");
  }

  return data as Work[];
}
```

**Внимание:** `/api/v1/works/` здесь приведён как пример. Адрес, поля и формат ответа ещё должны быть согласованы.

`as Work[]` — это только утверждение типа для TypeScript, а не настоящая проверка содержимого массива. Для реального API нужно проверять структуру объектов или применять согласованную библиотеку валидации.

## Твоя задача

Самостоятельно объяснить:

3. Что делает `await fetch()`?
4. Что происходит, если сервер возвращает 500?
5. Почему `fetch` сам по себе не отклоняет Promise при HTTP 404 или 500?
6. Для чего нужна проверка `response.ok`?
7. Почему нельзя без проверки доверять JSON с сервера?

# 9. Восьмое задание — обработка ошибок и повторных запросов

Представь ситуацию:

Пользователь быстро вводит:

```
Б
Бе
Бет
Бетх
Бетховен
```

Если ты отправляешь отдельный запрос на каждое изменение поисковой строки, сервер может получить много запросов.

Кроме того, старый запрос может завершиться позже нового и заменить свежие результаты устаревшими.

Поэтому нужно познакомиться с двумя технологиями.

## Debounce

Debounce — задержка перед выполнением действия.

Например, запрос отправляется только после того, как пользователь перестал печатать на 400 мс.

## AbortController

`AbortController` позволяет отменить предыдущий `fetch`, когда его результат уже не нужен.

Пример:

```
const controller = new AbortController();

fetch("/api/v1/works/", {
  signal: controller.signal,
});

// Отмена запроса
controller.abort();
```

В React отмену предыдущего запроса обычно помещают в функцию очистки `useEffect`.

### Дополнительное задание

После того как освоишь обычный `fetch`:

- Реализовать debounce.
- Использовать AbortController.
- Не показывать ошибку пользователю при ожидаемой отмене запроса.
- Проверить быстрый ввод.
- Проверить, что старый ответ не перезаписывает новый.

Эту часть выполнять после согласования поиска через API. Пока локальный `filter()` работает без сетевых запросов, debounce и AbortController не обязательны.
