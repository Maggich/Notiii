## Твоя цель

Помочь команде пользоваться одной папкой `Notiii`, запустить Docker Compose, найти настоящие ошибки среды и повторить готовый сценарий приложения. Ты не пишешь вместо студентов модели, API или React-компоненты.

## Что ты меняешь

Обычно код не меняешь. Если нашёл проблему в Docker-конфигурации или стартовых командах:

- [ ] Сначала покажи преподавателю точную ошибку и предложи минимальное исправление.
- [ ] Меняй конфигурацию только после разрешения преподавателя.
- [ ] После исправления повтори ту же команду и покажи результат.
- [ ] Не удаляй PostgreSQL volume, не выполняй `docker compose down -v`, не удаляй папки проекта.

### Как помогать группе

Попроси студента открыть его `Task.md` и назвать текущий пункт. Пусть он сам вводит команды, читает ошибку и меняет свой код; ты помогаешь проверить Docker, контейнеры и логи. Записывай наблюдаемый факт («backend Restarting», «URL вернул HTTP 503»), а не догадку («Django сломан»). Не редактируй код студента за него.

- [ ] **Часть 1. Убедись, что открыт корень проекта**

Открой PowerShell в переданной папке `Notiii` и выполни:

```powershell
Get-Location
Test-Path .\README.md
Test-Path .\docker-compose.yml
```

Путь должен оканчиваться на `Notiii`, обе проверки должны вернуть `True`.

Если путь не тот, в VS Code выбери **File → Open Folder** и открой переданную папку `Notiii`; затем снова открой терминал через **Terminal → New Terminal** и повтори проверки. Не запускай команды из другой копии проекта.

- [ ] **Часть 2. Проверь Docker**

Выполни команды по одной:

```powershell
docker version
docker compose version
docker compose config --quiet
```

Если `docker version` показывает ошибку Engine/daemon, Docker Desktop не готов. Запиши весь текст ошибки и попроси преподавателя решить, можно ли продолжать без контейнера. Не заявляй, что причина в приложении, пока Engine не отвечает.

Если предыдущие команды прошли, запусти:

```powershell
docker compose up --build -d
docker compose ps
```

Проверь, что контейнеры `db`, `backend`, `frontend` не находятся в состоянии `Exited` или `Restarting`.

Что должно быть видно: у `docker version` есть Client и Server; отсутствие Server означает, что Docker Engine не отвечает. `docker compose config --quiet` при успехе обычно ничего не печатает. `up --build -d` собирает и запускает контейнеры в фоне. `ps` показывает настоящее состояние. Если ошибка — сохрани весь текст; не запускай команды с `-v` и не удаляй данные.

- [ ] **Часть 3. Проверь health**

Выполни:

```powershell
Invoke-RestMethod http://localhost:8000/api/v1/health/
Invoke-RestMethod http://localhost:5173/api/v1/health/
```

Оба запроса должны вернуть `status=ok` и `service=music-sheet-library-api`. Второй запрос проверяет, что Vite proxy передаёт запрос Django.

Если запрос не работает, проверяй по порядку:

- [ ] `docker compose ps` — жив ли нужный контейнер.
- [ ] `docker compose logs --tail 100 db` — готова ли PostgreSQL.
- [ ] `docker compose logs --tail 100 backend` — запускается ли Django.
- [ ] `docker compose logs --tail 100 frontend` — запускается ли Vite.
- [ ] Сначала почини первый сервис с ошибкой; не меняй одновременно несколько конфигураций.

Если ответ `status=unavailable`/HTTP 503, Django уже ответил, но проверь связь с PostgreSQL: сначала логи `db`, потом `backend`. Если порт 8000 работает, а 5173 нет — проверь `frontend` и proxy. Если оба не работают — сначала проверь состояние контейнеров и Docker Engine. После исправления повтори тот же URL и запиши новый фактический результат.

- [ ] **Часть 4. Помогай студентам без выполнения их кода за них**

- [ ] Перед началом спроси каждого, какой файл его Task.md разрешает менять.
- [ ] Не допускай, чтобы два человека одновременно редактировали один файл.
- [ ] При ошибке попроси студента прочитать первую относящуюся к делу строку и назвать следующий диагностический шаг.
- [ ] Помогай запуску: Docker, контейнеры, логи, доступ к URL.
- [ ] Не принимай код и не выставляй оценки вместо преподавателя.
- [ ] Если студент изменил чужой файл, останови работу и сообщи преподавателю; не удаляй его изменения сам.

- [ ] **Часть 5. Повтори готовый путь каталога**

После того как модели, миграция, API и frontend готовы и проверены их владельцами:

- [ ] Посмотри, что `docker compose ps` показывает работающие сервисы.
- [ ] Открой `http://localhost:5173`.
- [ ] В DevTools → Network найди `GET /api/v1/works/`, проверь статус и JSON.
- [ ] Проверь поиск по названию, поиск по автору и запрос без совпадений.
- [ ] С разрешения преподавателя останови backend командой `docker compose stop backend`; проверь сообщение ошибки на экране; затем включи его командой `docker compose start backend` и проверь, что запрос снова работает.
- [ ] Попроси другого человека повторить шаги по корневому `README.md`.

Для завершения обычной работы останови контейнеры без удаления данных:

```powershell
docker compose down
```

Не добавляй `-v`: это удалит локальные данные PostgreSQL.

## Твоя задача принята, когда

- [ ] Проект запустился командами из README; если мешает Docker Engine, сохранён точный текст ошибки и это записано как блокер.
- [ ] Health ответил ожидаемым JSON напрямую через порт 8000 и через Vite proxy на порту 5173.
- [ ] Ты показал логи/команды, по которым различил ошибку Docker, PostgreSQL, Django и Vite.
- [ ] Другой человек смог повторить запуск.
- [ ] Ты помогал студентам найти причину, но они сами меняли и объясняли свой код.

### Как записать помощь преподавателю

Для каждого сбоя сообщи четыре факта: `Команда или URL`; `точный результат`; `что уже проверено`; `следующий безопасный шаг`. Не проси студентов присылать пароли, токены или содержимое `.env`.
