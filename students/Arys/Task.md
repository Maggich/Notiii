## Часть 1. Автотесты health — можешь начать сразу

### Как работать

Открой `Notiii` в VS Code (**File → Open Folder**). Файлы ищи в Explorer слева; терминал открывай через **Terminal → New Terminal**. Меняй только перечисленные файлы. Если проверка не совпала с ожиданием — остановись, поставь `[-]`, скопируй первую полную ошибку в «Блокер» и позови преподавателя/Кирилла. Не пропускай красный тест и не говори «работает», пока сам не увидел результат.

- [ ] **Шаг 1. Проверь, как устроен endpoint**

Открой `backend/catalog/views.py`, `backend/catalog/urls.py`, `backend/config/urls.py`. Проследи путь `/api/v1/health/` до функции `health`. Спроси себя: какой ответ при рабочей базе? Какой ответ при ошибке базы?

Проследи маршрут по цепочке: `config/urls.py` подключает `api/v1/`; `catalog/urls.py` сопоставляет `health/`; `views.py` содержит функцию `health`. Покажи преподавателю точные статус-код и JSON, написанные в функции. Не утверждай, что видел 503, если ты его не запускал или тестировал.

- [ ] **Шаг 2. Создай тесты**

Открой уже подготовленный `backend/catalog/test_health.py` и замени TODO-комментарий тестами на Django `TestCase` и `self.client.get()`.

Сделай два теста:

- [ ] Успех: подмени `catalog.views.connection.ensure_connection` так, чтобы вызов прошёл; проверь статус 200 и весь JSON: `{"status":"ok","service":"music-sheet-library-api"}`.
- [ ] Ошибка базы: подмени тот же вызов так, чтобы он выбросил `django.db.utils.OperationalError`; проверь статус 503 и весь JSON: `{"status":"unavailable","service":"music-sheet-library-api"}`.

Ошибка базы должна моделироваться в тесте; не выключай PostgreSQL для этого теста.

Успешный тест проверяет статус **и весь JSON**, а не один ключ. Для второго теста подмени `catalog.views.connection.ensure_connection`, чтобы он выбросил `OperationalError`; затем проверь статус 503 и все поля JSON. Ошибку изображает тестовый mock, поэтому PostgreSQL выключать не требуется.

- [ ] **Шаг 3. Докажи, что тест обнаруживает поломку**

Запусти:

```powershell
docker compose exec backend python manage.py test catalog.test_health
```

Сначала запусти неизменённые тесты и дождись окончания. Для демонстрации временно поставь неправильный ожидаемый HTTP-код в одном тесте, запусти команду и покажи, что конкретный тест упал из-за несовпадения. Сразу верни правильный код, сохрани файл и снова запусти команду: ожидаемый итог — `OK`. Не оставляй временную поломку.

Временно поменяй ожидаемый статус одного теста на неправильный. Запусти тот же тест и покажи преподавателю красный результат. Верни правильное ожидание и запусти тест снова: ожидается `OK`. Не оставляй временную поломку в файле.

## Часть 2. API списка — начинай после Мадиара

- [ ] Преподаватель подтвердил модель Мадиара и точный пример JSON. До этого пункта не создавай URL или обработчик списка.

До подтверждения выполняй только часть 1. Попроси преподавателя показать готовую модель и письменно зафиксированный пример ответа. Перепиши точные поля в тест-план; не придумывай их самостоятельно.

Сначала преподаватель должен подтвердить модель и образец JSON. Без этого не создавай endpoint списка. Предлагаемый маршрут:

```http
GET /api/v1/works/
GET /api/v1/works/?q=соната
```

Ответ содержит `count` и `results`. Каждый элемент имеет согласованные поля произведения и композиторов. Если ничего не найдено — HTTP 200 и пустой `results`.

- [ ] **Шаг 4. Составь примеры перед кодом**

Покажи преподавателю четыре ожидаемых результата: полный список; совпадение по названию; совпадение по автору; ничего не найдено. Запиши точные JSON-поля по его утверждённому контракту. Не добавляй фильтр, сортировку или пагинацию, если их не утвердили.

- [ ] **Шаг 5. Добавь URL и обработчик**

- [ ] В `backend/catalog/urls.py` добавь `works/`.
- [ ] В `backend/catalog/views.py` создай обработчик, который читает данные из модели Мадиара.
- [ ] Верни JSON строго по утверждённому контракту.
- [ ] Для q ищи только по утверждённым полям. Если связь с несколькими композиторами возвращает одну работу повторно, убери дубли в QuerySet.
- [ ] GET не должен менять базу.

Простой способ собрать JSON: начни с `Work.objects.all().prefetch_related("composers")`; если q не пустой, добавь фильтр по разрешённым полям; при поиске через связь используй `.distinct()`. Для каждой строки собери Python-словарь и верни через `JsonResponse`. Не делай запрос к базе отдельно для каждого композитора.

- [ ] **Шаг 6. Напиши содержательные тесты API**

В уже созданном `backend/catalog/test_works.py` добавь тесты. Создавай записи прямо в тесте через `setUp`/`TestCase`; не надейся на заранее заполненную базу. Покрой:

- [ ] список не пустой и содержит правильные поля;
- [ ] поиск по названию;
- [ ] поиск по композитору;
- [ ] совпадение сразу по нескольким связанным авторам не дублирует произведение;
- [ ] неизвестный запрос даёт 200 и пустой список;
- [ ] пустой параметр q обрабатывается согласно решению;
- [ ] порядок стабилен, если сортировка утверждена;
- [ ] GET не создаёт, не изменяет и не удаляет записи.

Запускай тесты командой:

```powershell
docker compose exec backend python manage.py test catalog.test_health catalog.test_works
```

Для одного теста временно измени ожидаемый ответ: он должен упасть. Верни ожидание и снова получи `OK`. Запиши увиденный результат преподавателю; не записывай выдуманный.
