## Твоя цель

Сделать аккуратные React-компоненты, которые отображают произведения, переданные через props. Компоненты не должны сами обращаться к серверу. Поиск и сетевое состояние ведёт Халил.

## Какие файлы ты меняешь

### Как работать

Открой корень `Notiii` в VS Code (**File → Open Folder**). В Explorer слева раскрой `frontend` → `src` → `components`. Папка и три файла `WorkCard.tsx`, `WorkGrid.tsx`, `WorkGrid.css` уже созданы с TODO-комментариями. Открой нужный файл и замени TODO своей реализацией; новые файлы не создавай. Сохраняй `Ctrl+S`. После каждого пункта покажи файл преподавателю. Если не знаешь точное поле/тип — остановись и спроси Халила, не угадывай.

- `frontend/src/components/WorkCard.tsx` — одна карточка.
- `frontend/src/components/WorkGrid.tsx` — список карточек.
- `frontend/src/components/WorkGrid.css` — оформление.

Папка `frontend/src/components` и файлы компонентов уже подготовлены. Открой указанные файлы и замени TODO-комментарии своей реализацией. Не меняй `App.tsx`, `CatalogPage.tsx` или `api/works.ts` Халила. Для типа работы используй согласованный тип Халила; не создавай второй несовместимый тип.

- [ ] **Шаг 2. Сделай компонент `WorkCard`**

- [ ] Компонент получает одну работу через props.
- [ ] Показывает название, композиторов и сложность.

Создай компонент по частям: сначала получи `work` через props и покажи заголовок; сохрани и проверь build. Затем покажи имена композиторов и сложность. - [ ] **Шаг 3. В уже созданном `WorkGrid.tsx` замени TODO-комментарий компонентом.**

- [ ] Компонент получает массив работ через props.
- [ ] Для каждого элемента выводит `WorkCard`.
- [ ] Передаёт стабильный `key={work.id}`.
- [ ] Если массив пустой, покажи сообщение «Ничего не найдено».
- [ ] Если массив непустой, покажи все карточки; пустое сообщение в этом случае отсутствует.
- [ ] Loading и ошибка принадлежат странице Халила; не рисуй их как пустой список.

Сначала покажи компоненты преподавателю на временном локальном примере. Если ты создала временные записи в самом компоненте, удали их до подключения к настоящей странице. Компонент не должен хранить фиктивные данные.

В сетке получи массив через props и используй `.map(...)`, чтобы вернуть отдельный `WorkCard` на каждую работу. `key` — `work.id`, не номер элемента. Проверь два случая: `[]` показывает только «Ничего не найдено»; массив из двух объектов показывает ровно две карточки. Loading и ошибка принадлежат странице Халила, не сетке.

- [ ] **Шаг 5. Проверь проект**

В PowerShell из корня `Notiii` перейди в папку frontend и выполни:

```powershell
cd frontend
npm run build
npm run lint
```

Затем проверь на странице:

- [ ] Два переданных объекта показывают две карточки.
- [ ] У карточки с двумя композиторами видны оба имени.
- [ ] Пустой массив показывает только «Ничего не найдено».
- [ ] На ширине 375 px нет горизонтальной прокрутки.

Проверь по очереди: широкое окно — несколько колонок; ширина 375 px — одна колонка; длинное название переносится и не раздвигает страницу; несколько имён композиторов видны полностью. Не скрывай горизонтальную прокрутку через `overflow-x: hidden`, если текст просто обрезался.
- [ ] Если есть ссылка — Tab переводит на неё фокус, фокус заметен.

Чтобы проверить 375 px в Chrome/Edge: открой страницу, нажми `Ctrl+Shift+I`, затем `Ctrl+Shift+M`, выбери или введи ширину `375`. Если снизу появилась горизонтальная прокрутка, найди слишком широкий элемент в DevTools и исправь свой CSS.

Ручной пример доказывает только отображение компонента. Он не доказывает, что API работает.
